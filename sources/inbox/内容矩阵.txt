## 任务：建设机场品牌库与品牌内容矩阵

请读取项目中已有的：

- 机场品牌清单
- 品牌 Logo、配色及图表样式文件
- 关键词优先级文件
- GEO 长尾问题库
- 已有文章与页面数据

在现有 Astro 项目中新增一个独立路由的“机场品牌库”页面，最终静态生成完整 HTML。不要创建脱离现有网站架构的孤立 HTML 文件。

### 一、品牌数据整理

提取清单中的所有机场品牌，建立统一的品牌数据结构，包括：

- 品牌名称与 slug
- Logo 和品牌视觉
- 官方网站
- 品牌简介
- 主要套餐与价格
- 线路及节点特点
- 支持协议
- 客户端兼容性
- 流媒体支持情况
- 适合人群
- 优点与限制
- 风险提示
- 信息来源
- 数据核实日期
- 最近更新时间

不得编造价格、测速、节点数量、运营状态、用户评价或亲自使用经历。没有可靠资料的字段统一标记为“待核实”，不得以确定语气发布。

### 二、机场品牌库页面

设计并实现机场品牌库页面，至少包括：

- 页面标题和品牌库说明
- 品牌搜索
- 条件筛选与排序
- 品牌卡片
- 分类或标签导航
- 风险及数据状态提示
- 品牌详情入口
- 更新时间说明
- 移动端适配
- 空状态与无结果状态

页面视觉应读取并继承品牌图表样式文件，同时符合当前网站的 Site DNA、设计系统和响应式规范。

不得机械复制其他项目的卡片、首页或品牌库结构。

### 三、品牌内容大纲

针对清单中的每个机场品牌分别建立独立的内容大纲。每份大纲至少包含：

- 页面主要搜索意图
- 目标用户
- 主关键词
- 次级关键词
- GEO 长尾问题
- 建议 Title
- Meta Description
- H1
- 推荐 URL
- 文章核心结论
- 品牌背景与基础信息
- 套餐、线路和协议说明
- 适用客户端
- 优点、限制及风险
- 适合与不适合的人群
- 与同类品牌的差异
- 常见问题
- 信息来源与更新时间
- 相关内容与内部链接
- 自然且透明的 CTA

不同品牌文章必须具有独立的信息增量和章节结构，不得只替换品牌名称、关键词和少量句子。

### 四、关键词与长尾问题映射

读取关键词优先级文件，为每个品牌页面建立关键词映射，包括：

- 一个主要关键词
- 若干次级关键词
- 品牌相关长尾词
- 问题型搜索词
- Search Intent
- 用户决策阶段
- 对应内容章节
- 所属主题集群
- 上游入口页面
- 下游转化页面
- 与其他品牌页面的关键词边界

避免不同页面竞争相同关键词。无法自然融入文章的关键词不得强行使用。

读取长尾问题库，将有真实搜索价值且与品牌相关的问题转化为正文小节、条件判断、故障说明、比较维度或 FAQ。

FAQ 只能使用页面正文中真实回答的问题，不得为了结构化数据批量堆砌问答。

### 五、SEO 与 GEO 要求

每个可索引品牌页面必须具备：

- 唯一的 Title、Meta Description 和 H1
- 清晰的标题层级
- 正确的 canonical
- Breadcrumb
- 语义化 HTML
- 自然内部链接
- 图片 alt、尺寸和响应式输出
- Article 或适用的页面 Schema
- BreadcrumbList
- 品牌库页面的 ItemList
- 真实可见内容对应的 FAQPage（仅适用时）
- 发布时间、核实日期和最近更新时间

GEO 内容表达应采用：

- 先回答核心问题
- 清晰定义品牌与服务实体
- 使用条件化结论，避免绝对化推荐
- 明确数据来源、测试范围和信息日期
- 提供适合与不适合人群
- 使用自然的比较、步骤、优缺点和风险说明
- 保持品牌名称、实体信息和结论一致

目标是提高内容被 Google、Bing 及生成式搜索系统抓取、索引、理解、摘要、引用和推荐的可能性，不得承诺排名、收录、流量或引用结果。

### 六、内部链接矩阵

建立以下链接关系：

- 品牌库 → 品牌详情页
- 机场推荐专题 → 品牌详情页
- 品牌详情页 → 相关评测
- 品牌详情页 → 客户端教程
- 品牌详情页 → 协议知识
- 品牌详情页 → 风险预警
- 比较文章 → 对应品牌详情页
- 教程与知识文章 → 相关选择指南
- 风险页面 → 可选替代方案

链接必须符合用户下一步需求，不得机械插入关键词锚文本。

### 七、交付文件

最终至少交付：

- 机场品牌结构化数据文件
- 机场品牌库页面
- 品牌卡片与筛选组件
- 每个品牌的内容大纲
- 品牌关键词映射表
- GEO 长尾问题映射表
- 内部链接矩阵
- Schema 配置
- 数据来源及更新时间记录
- QA 检查报告

### 八、验收要求

完成后必须检查：

- 项目能够正常构建
- 所有品牌都有唯一 slug
- 不存在重复路由
- 不存在空链接和无效详情入口
- 不存在虚构数据
- 不存在未标注的示例内容
- 不存在关键词互抢
- 不存在批量换词文章
- 品牌库在桌面端和移动端均可正常使用
- Schema 与页面真实可见内容一致
- 品牌页面已纳入 sitemap 和内部链接体系

先完成品牌数据审计与关键词映射，再实现品牌库页面。发现数据缺失时记录为“待核实”，继续完成可以安全实施的部分，不要擅自补写虚假事实。
